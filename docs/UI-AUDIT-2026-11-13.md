# DairyFlow UI and workflow audit — 13 November 2026

The findings below were fixed in the application. Verification used isolated demo and test databases. See VERIFICATION.md for the deployment state; synthetic test entries were never added to the live farm.

## Findings and changes

| Area | Cause found | Result |
| --- | --- | --- |
| Pregnancy counts | Separate dashboard, breeding and cattle calculations; some lists required an expected date or treated pregnancy as a production stage | Shared herd and breeding calculations. A cow can be both milking and pregnant. All current pregnancies appear, including those without a due date. Sold and merged animals do not count as active. |
| Drill-downs | Several query parameters were ignored; tab names and transaction links were wrong; date periods differed between totals and detail pages | Breeding filters, cattle profitability, health/vaccination, task and milk links honor their context. Reports preserve the chosen week/month/calendar-quarter/year. |
| Animal selection | Forms did not consistently apply the incoming cattle ID after loading options; several selects were uncontrolled | Shared selection handling across milk, heat, insemination, pregnancy testing, calving, health, vaccination, feeding, task and cattle-sale forms. Invalid/inactive linked animals show an error. |
| Stale totals | Saving an entry refreshed only part of the dependent data | Successful writes invalidate derived views, including dashboard totals. Errors display the server's useful message. |
| Heat and vaccination reminders | Different due windows, superseded vaccine doses, and server/browser timestamp differences | Shared calendar-day rules and a 30-day upcoming window. Latest vaccine dose per animal and vaccine; farm-timezone handling for heat timestamps on server and browser. |
| Calving | Milking pregnant cows were missing from the mother selector; missing calf details failed late | Active females remain selectable. Live births require calf tag and sex before submission. Stillbirth/abortion does not reuse hidden calf data; calving ease is retained. |
| Task completion | A general task checkbox could mark pregnancy care finished without changing the animal's lifecycle | Care tasks use Care & Work completion with evidence and stock handling. Dry-off completion updates production status. Team assignment uses actual team members. |
| Mobile layout | Overflowing button rows and filters; menu stayed open after navigation | Responsive wrapping, constrained content width, larger action targets and automatic mobile-menu closure. |
| Daily PDF | Generic raw-record output was lengthy and difficult to scan | Two-column A4 brief with cow milk grid, customer tables, clinical notes, actionable work and concise activity summaries. Print opens the same PDF layout. |

## Daily report workflow

Open **Reports → Daily farm brief**, select a date, then choose **Download daily PDF** or **Open print layout**. The default is yesterday; Today and Yesterday shortcuts are available. Past dates open their latest saved revision when available. Choose Rebuild preview from current records explicitly when reviewing corrections; dates without a saved revision use a clearly labelled generated preview.

The brief includes:

- Every milking cow, with morning/evening quantities and configured additional sessions. A missing entry is `--`; recorded zero stays `0.0`. Animals with entries remain included even if their current production status has changed.
- Opening milk, production, discarded milk, sales, calf feed/other allocations, and the unallocated difference.
- Sales by customer/product, daily payments received, and each customer's outstanding debit or advance credit as of the report date. Linked legacy and dairy sales are counted once.
- Health issues, treatments, vaccination/deworming records, recorded supply quantities and milk-withdrawal information.
- Assigned work for today, tomorrow and the next 30 days, all overdue work, undated open tasks, and work completed on the report day. Countdown labels show days left, due today or days overdue.
- Expected heat, pregnancy tests, dry-off, calving, vaccinations, and a daily pre-calving diet/supplement review during the last 20 days. Approved animal-specific diets take precedence over group diets. Missing or conflicting plans request review; the software does not invent feed or medicine doses.
- Other recorded farm activities, financial entries and stock exceptions. Repetitive entry audit events are summarized by module; the full detail remains in the on-screen report and Excel export.

Dry-off and calving reminders remain until the corresponding event is recorded. For planned culling or other farm work, create a dated task linked to the animal and assign an owner; it repeats while open. Complete the task when the work is done and record the animal's actual status. Open work for animals that have left the active herd is excluded from current reports.

## Verification

- TypeScript check and client/server production build pass.
- Initial UI pass: **64 tests passed, no failures**. The expanded workflow and Android verification is recorded below. Regression coverage includes five mixed-status pregnancies with only one known due date, farm-day boundaries, latest vaccination doses, dry-off completion, culling countdowns, approved transition diets, customer debit/credit, sale deduplication, and missing-versus-zero milk.
- Browser checks in the isolated demo verified the pregnancy card/list, selected-cattle context in all ten entry workflows, saving milk, report-period drill-downs, and mobile-menu closure.
- Mobile checks at 320 and 390 pixels covered cattle, breeding, health, care, milk, finances and reporting. No page-level horizontal overflow was observed on the checked routes; wide detail tables scroll inside their containers. No browser console errors were observed.
- The rendered sample with **30 cows, 59 milk entries, 8 customer sales/accounts, health/treatment notes and 14 work items fits two A4 pages**. Both pages were visually inspected; text extraction verified all 30 tags and the required sections. Raw entry audit events do not generate a second copy of every milk row.
- No schema migration is introduced by these changes.

## Limits and release considerations

- The user's actual production herd still needs a read-only reconciliation after deployment. These fixes remove inconsistent application rules but do not guess or overwrite animal pregnancy status or missing expected dates.
- The 1–2 page layout is verified for the sample scale above. Unusually large herds, long treatment instructions, many customers or extensive overdue work can add pages; records are not silently omitted to force a page limit.
- Historical live previews use dated activity and as-of customer balances, but animal/work state is current at generation. Saved revisions preserve the snapshot generated at that time. Use saved revisions for historical operational review.
- Build succeeds with the existing PostCSS warning and a large JavaScript bundle warning. Bundle splitting remains a separate mobile-performance improvement; this audit did not measure real-device network performance.
- Existing deployment documentation describes a production-only owner-login integration. Any release must preserve that integration and follow the repository's established deployment procedure.


## Extended workflow fixes and Android release

- Reconciled durable heat, pregnancy-test, dry-off, calving, pre-calving diet review, heifer-readiness and vaccination work. Correcting farm intervals updates open derived work; manually postponed work retains its approved date. Reconciliation does not continuously change animal revisions. Due/overdue alerts persist and return on the next farm day if dismissed without completing the work.
- Calving, pregnancy testing and vaccination tasks link to their actual entry forms with the animal selected. A checkbox cannot falsely complete them. Abortion records close the pregnancy and appear in the animal history without counting as a successful calving.
- Added dated exit/archive/reactivation with reasons and history preservation. Incorrect cattle transactions can be reversed with an explicit correction record. Voided balances and reversed receipts no longer inflate receivables. Animal purchases and their first payment save atomically.
- Vaccines without catalogue IDs keep independent follow-up schedules. New doses supersede old reminders; selected vaccination dates determine the next due date. Protocol age eligibility uses the date of the scheduled action. Critical illness, withdrawal release and quarantine have follow-up work.
- Added coverage reviews for breeding, vaccination, deworming, calves, treatments, biosecurity, nutrition, hygiene, milk quality, equipment, welfare, manure/waste, stocks and accounts. Staff can assign recurring reviews with approved instructions; recurrence retains its coverage category. Farm-specific clinical plans and doses still require configuration and approval.
- Prevented future actual milk allocations and corrections that would leave sales above available milk. Milk-drop rules require complete configured sessions. Stale alerts are retired; one farm's worker failure does not stop other farms. Interrupted notification deliveries require review before retrying.
- Added an Android app with bundled UI, app-private SQLite cache/outbox, HTTPS session authentication, scoped offline records, persistent retry IDs, temporary record-ID resolution, visible conflicts and local due-task reminders. Sales/customer/payment entry joins the same queue. First launch requires an online sign-in and download. The VPS validates every queued entry before committing it.
- Foreground sync runs on reconnect/resume and approximately every minute. Android WorkManager requests network-connected background sync every 15 minutes; Android controls actual execution according to battery/background restrictions. Local reminders use the latest downloaded task data.
- Phone uploads, imports, administrative settings and new server-generated PDF/Excel documents require a connection. Offline screens use downloaded records and explicitly identify pending entries. Records created by other users appear after the next successful sync. No physical handset or emulator was attached during this release; native SQLite/network behavior was tested with Robolectric and a local mock HTTP server.
- The release APK is built by `npm run android:build` and placed in `artifacts/DairyFlow.apk`. `VITE_FARM_SERVER` may prefill the HTTPS address; the first-launch screen validates it. Release signing material is in ignored `.android-signing/`. Back up that directory privately: future APK updates must use the same signing key. It is never packaged in the app or committed.
- Compatible dependency updates removed the reported critical proxy-address advisory. Remaining dependency advisories requiring major-version/override changes are not a claim of a completed security audit; in particular Zod 3 needs a separately validated migration. HTTP body size and sign-in limits remain enforced; authenticated session polling no longer consumes the login-attempt allowance.
